# k8s-hardening-image-signing

Deploys the Kyverno `verify-image-signatures` ClusterPolicy for CIS Kubernetes Benchmark section 5.5 (supply chain security). The policy enforces cosign signature verification on images from your registry; it reads the cosign public key from a Kubernetes Secret (`cosign-key` in namespace `kyverno`) that is materialized by an ExternalSecret pulling from Vault.

## Structure

```
application.yml                 # ArgoCD Application — cross-repo source k8s-hardening-cis@master:12-image-signing-and-scanning
cosign-key.externalsecret.yml   # ESO sync-wave "-1" — creates Secret cosign-key in kyverno namespace from Vault
README.md                       # This file — one-time Vault seed and ESO role extension runbook
```

Sync-wave ordering within this Application:

| Wave | Resource | Purpose |
|------|----------|---------|
| -1 | ExternalSecret `cosign-key` | Secret materializes before the ClusterPolicy attempts to resolve it |
| 0 (default) | ClusterPolicy `verify-image-signatures` | Policy is applied after the Secret exists |

## Vault Setup

Seed the cosign public key before the first sync. This is a **one-time manual step** per cluster; the public key (`cosign.pub`) is generated by the signing workflow documented in `k8s-hardening-cis/12-image-signing-and-scanning/cosign-sign-verify.md`.

> **SECURITY**: Only the PUBLIC key (`cosign.pub`) is seeded here. The private key (`cosign.key`) must NEVER be committed to this repo, to k8s-hardening-cis, or to any other git repository.

```bash
TOKEN="$(kubectl -n vault get secret vault-root-token -o jsonpath='{.data.token}' | base64 -d)"

kubectl exec -n vault vault-0 -c vault -- sh -c "
  VAULT_ADDR=http://127.0.0.1:8200 VAULT_TOKEN=$TOKEN \
  vault kv put secret/k8s-hardening/cosign pub='<cosign.pub contents>'
"
```

Replace `<cosign.pub contents>` with the single-line or multi-line contents of your `cosign.pub` file. Wrap multi-line PEM in single quotes as shown.

### Vault Policy

```bash
kubectl exec -n vault vault-0 -c vault -- sh -c "
  VAULT_ADDR=http://127.0.0.1:8200 VAULT_TOKEN=$TOKEN \
  vault policy write k8s-hardening - <<EOF
path \"secret/data/k8s-hardening/*\" {
  capabilities = [\"read\"]
}
EOF
"
```

### Extend ESO role

Read the current policy list first — **never blind-overwrite** the existing policies attached to the `external-secrets` Vault role. Appending without reading first will silently drop all other apps' read permissions.

```bash
CURRENT=$(kubectl exec -n vault vault-0 -c vault -- sh -c \
  'VAULT_ADDR=http://127.0.0.1:8200 VAULT_TOKEN='"$TOKEN"' vault read -field=policies auth/kubernetes/role/external-secrets' \
  | tr -d '[]' | tr ' ' ',')

kubectl exec -n vault vault-0 -c vault -- sh -c \
  'VAULT_ADDR=http://127.0.0.1:8200 VAULT_TOKEN='"$TOKEN"' vault write auth/kubernetes/role/external-secrets \
    bound_service_account_names="external-secrets" \
    bound_service_account_namespaces="external-secrets" \
    policies="'"$CURRENT"',k8s-hardening" ttl="1h"'
```

## Deploy

```bash
kubectl apply -f k8s-hardening-image-signing/application.yml
# then trigger the first sync manually (no automated sync — ARGO-04):
argocd app sync k8s-hardening-image-signing
```

## Verification

```bash
# ExternalSecret materialized the Secret
kubectl -n kyverno get secret cosign-key

# ExternalSecret sync status
kubectl -n kyverno describe externalsecret cosign-key

# Force ExternalSecret reconcile if needed
kubectl -n kyverno annotate externalsecret cosign-key \
  reconcile.external-secrets.io/requested-at="$(date --iso-8601=seconds)" --overwrite

# ClusterPolicy applied and in Audit mode
kubectl get clusterpolicy verify-image-signatures -o jsonpath='{.spec.validationFailureAction}'
# should print: Audit
```

## Notes

- **Registry placeholder**: `12-image-signing-and-scanning/kyverno-verify-image-signatures.yaml` has `imageReferences: your-registry.example.com/*`. Replace with your actual registry before enabling Enforce mode.
- **Audit vs Enforce**: The policy starts in `validationFailureAction: Audit`. Check `kubectl get policyreport -A` to confirm all existing signed images pass before flipping to `Enforce`.
- **Private key**: `cosign.key` must stay on the CI signing host only. It must never be committed to git or stored in Vault. Only `cosign.pub` belongs here.
- **Depends on**: The `kyverno/` operator app (wave 0) and `k8s-hardening-kyverno-policies` app (wave 1) must be synced before enabling Enforce mode on this policy.
